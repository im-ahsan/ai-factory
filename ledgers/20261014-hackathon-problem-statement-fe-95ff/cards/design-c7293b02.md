# Approve the design

Run 20261014-hackathon-problem-statement-fe-95ff. The build follows the approved mock and clickable demo: its screens, states, sample content and look are what gets built.

Flow: One responsive Feedlot web app. All signed-in users share the same menu, in this order: Overview → Lots → Inventory → Rations → Feeding plans → Feeding log → Lot weights → Yard summary → Feed-to-Gain. Administrators also get conditional links from Overview to Accounts, Sync, and Demo; Operators never see those links. Sign-in is email and password only, with no registration or SSO. Design guidance for DESIGN.md: use dense, readable operational tables and one contextual headline figure rather than dashboard card grids; filters apply immediately; use a plain bar, hairline separators, and restrained status color. Layouts use a centered max-width container, CSS Grid where useful, clear non-overlapping zones, and responsive tables that become labeled stacked rows on narrow screens; full-height layouts use min-h-[100dvh], never h-screen. NEVER DO: emojis; Inter; generic serif fonts such as Times New Roman, Georgia, or Garamond; pure black (#000000); neon or outer-glow shadows; oversaturated accents; excessive gradient text; custom cursors; overlapping elements; equal three-column card layouts; generic names; fake round-number stats; AI clichés; filler scroll prompts; broken Unsplash links; centered hero sections. Replace four KPI cards and sparklines with one sourced headline metric plus a dense table; replace feature-card grids with ordered records and real operational detail; replace glass or gradient surfaces with solid bordered surfaces; use icons only when they speed recognition. No marketing hero or ticketing/seat-picker patterns.
